# Статусные модели сущностей

Статусные переходы — самая частая зона регрессий, поэтому вынесены в отдельный документ: тесты проверяют именно переходы, а не только конечные состояния.

## Подписка (`follows.status`)

```
            публичный аккаунт
   [нет] ─────────────────────────► accepted ──unfollow──► [нет]
      │
      │     приватный аккаунт
      └──────────────► pending ──accept──► accepted ──unfollow──► [нет]
                          │
                          └──reject──► [нет]
```

Проверяется в `tests/e2e/user_private/test_private_follow_flow.py`: подписка на приватный аккаунт обязана уйти в `pending` и стать `accepted` только после подтверждения владельцем.

## Пост

```
   created ──PATCH (≤ 15 мин)──► edited ──DELETE──► is_deleted = true
      │                                                     ▲
      └────────────────── DELETE ───────────────────────────┘
```

- Редактирование доступно только автору и только внутри 15-минутного окна. Проверка истечения окна требует `utils/db_handler.age_post()` — через API прошлое не воспроизвести.
- Удаление мягкое: запись остаётся в БД с `is_deleted = true`, API её больше не отдаёт.
- Флаг `is_pinned` независим от жизненного цикла: закреплённым может быть не более одного поста автора.

## Пользователь

```
   registered ──admin PATCH is_verified──► verified
        │
        └──admin PATCH is_active=false──► banned ──is_active=true──► active
```

Роль меняется отдельным полем: `user → moderator → admin`. Забаненный пользователь сохраняет возможность логина, но защищённые методы отдают 403 — это проверяется негативными тестами.

## Комментарий

Вложенность ограничена тремя уровнями: `depth 0 → 1 → 2 → 3`, попытка ответить на комментарий с `depth = 3` отклоняется. Удаление, как и у поста, мягкое.

## Уведомление

```
   created (is_read = false) ──read | read-all──► is_read = true
```

Уведомления создаются побочным эффектом чужих действий (лайк, комментарий, подписка), поэтому проверяются в сквозных флоу, где эти действия реально выполняются.
